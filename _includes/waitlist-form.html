{%- comment -%} The waitlist sign-up form. Sign-up is invite-only, so this — not a link to the app — is the primary call to action on the site. It lives inside the waitlist dialog (_includes/waitlist-modal.html); the buttons on the page only open that dialog. Params: id required, unique per instance (ids and the label/field association must not collide if a page ever renders this more than once) Posts to the API's public POST /v1/waitlist (site.api_base), which answers 204 for every well-formed address whether it's new, already queued, or already invited — so there is exactly one success message and it never reveals anyone's status. The form degrades to a plain mailto if JS is off; there's no server to post to otherwise, this being a static site. {%- endcomment -%} {%- assign fid = include.id -%}
